# AssureX Claim Engine

AssureX Claim Engine is an AI-assisted warranty-claim validation project based on the **AssureX Claim Engine SRS v1.0**. The system is intended to analyse warranty claims and support three outcomes:

- Valid Claim
- Invalid Claim
- Manual Review

The planned application will combine a Python classification model, a Google Teachable Machine image model, deterministic warranty rules, document/OCR processing, and a review workflow. The final claim decision will not be generated by an external generative-AI API.

> **Current status:** the dataset and Claim Summary Card pipeline are complete and validated. The Flask/MySQL application, trained models, OCR integration, rule engine, and reviewer workflow are not implemented yet. See [SRS_COMPLIANCE.md](SRS_COMPLIANCE.md) for the honest requirement status.

## Current implemented components

- 1,500 generated warranty claims
- Exact class balance: 500 Valid, 500 Invalid and 500 Manual Review
- Stratified 70/15/15 split: 1,050 / 225 / 225
- 2,100 training card images, 225 validation images and 225 test images
- Three configurable warranty policies in JSON
- Reusable Claim Summary Card generator
- Claim-to-image mapping
- Scenario definitions and dataset statistics
- Feature manifest separating model inputs from audit/rule outputs
- Synthetic document manifest with SHA-256 hashes
- Dataset validation report

## Requirements

Install Python 3.11 or later. The current dataset generator requires Pillow. The planned application will additionally require Flask, MySQL, SQLAlchemy, scikit-learn and an OCR wrapper.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
py -3 -m pip install --upgrade pip
py -3 -m pip install -r requirements.txt
```

If PowerShell blocks activation, run:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
```

Tesseract OCR is a separate external program and is not installed by `pip`. It will be documented when the OCR module is implemented.

## Reproduce the dataset

The generator uses a fixed default seed of 42. Test a new output folder first so an existing dataset is not deleted:

```powershell
py -3 .\dataset\dataset_generator_final.py --root .\dataset\reproduced_dataset
```

The command creates the CSV files, policies, cards, mappings and metadata in the selected output folder. Card generation may take several minutes.

Validate an existing dataset:

```powershell
(Get-Content .\dataset\validation_report.json -Raw | ConvertFrom-Json).status
```

Expected result:

```text
PASS
```

The canonical dataset currently in the repository has already been validated. Do not run the generator against the canonical folder unless you intend to replace it.

## Dataset design

The dataset is generated locally; no external warranty dataset is downloaded. The generator constructs raw claim facts first, calculates policy indicators deterministically, and assigns Claim IDs only after scenario generation and shuffling. Duplicate claims are created as real linked groups and are kept within one data split.

The following columns are retained for auditing but are not classifier inputs:

```text
claim_class
scenario
hard_fail_detected
warning_detected
manual_review_trigger
replacement_eligible
contradiction_detected
duplicate_claim
serial_number_status
warranty_status
claim_reporting_within_period
```

The model input list is recorded in `dataset/feature_manifest.json`.

## Planned application workflow

```text
Register/Login
  -> Register product
  -> Register warranty
  -> Create claim
  -> Upload documents
  -> OCR and user verification
  -> Python preprocessing
  -> Python model prediction and confidence
  -> Claim Summary Card
  -> Google Teachable Machine prediction and confidence
  -> Model comparison
  -> Warranty rules, contradictions and duplicate checks
  -> Final decision and explanation
  -> Manual review or closure
```

This workflow is a planned implementation target, not a claim that all stages currently exist.

## Running the current project

The dataset does not require a web server. To inspect the generator:

```powershell
notepad .\dataset\dataset_generator_final.py
```

To compile it:

```powershell
py -3 -m py_compile .\dataset\dataset_generator_final.py
```

Flask application setup will be added in a later SRS task. At present there is no `app.py`, database server configuration, sample web login, or deployed URL.

## Known limitations

- The dataset is synthetic and self-generated.
- The document manifest is synthetic metadata; real uploaded-document OCR is not implemented.
- No trained Python classifier or saved preprocessing pipeline exists yet.
- No Google Teachable Machine model has been trained or exported yet.
- No Flask/MySQL application, rule engine, decision engine, dashboard or reviewer workflow exists yet.
- The current repository is therefore a strong dataset foundation, not a complete competition application.
